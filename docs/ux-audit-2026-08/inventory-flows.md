FLOW 1 — New firm user: landing → login → accept-invite → first console session
1. `artifacts/landing/src/App.tsx` routes by pathname: "/" = `LandingPage` (marketing), "/login" = `Portal`, "/accept-invite" = `AcceptInvite`, "/reset-password". No SPA router — full page loads.
2. Invite email lands on /accept-invite?token=…; `AcceptInvite.tsx` strips the token from the URL (`takeQuerySecret`) and shows one card: optional full name, password, confirm. ~~It never shows who invited you, which firm, or the invited email address.~~ _(fixed R64: the card now shows account email, workspace and role — `invite-context`.)_
3. Failure paths: missing token → "Invitation link incomplete… ask your administrator to resend" (dead end, no self-serve); 400 → "invalid or expired" (same dead end); 409 → "account exists — sign in instead" with /login link.
4. Success card: "Your account is ready" → "Continue to sign in" → /login. CONTEXT LOSS: the flow knows the email but /login's `SignInPanel` starts blank — the brand-new user retypes the email they just activated.
5. /login: split layout — dark-teal `AccessStory` panel + sign-in form ("Sign in once… take you to the workspace for your role"). On success `DEFAULT_WORKSPACE` hard-navigates: firm_admin → /console/, firm_staff → /app/ (NOT console, though console admits firm_staff — a staff member must return to /login's tile hub to find the Accountant Console tile), operator → operator queue, auditor → /console/audit.
6. Console first session (`console/src/App.tsx` Home → `Portfolio`): with zero clients the user sees `PortfolioHeader` (Onboarding / Add client / Import clients buttons), the `GettingStartedCard` 5-step checklist (add client → invite owner → consent → first invoice → stamping) with inline "Add a client" and "Send an invite" links, and an `EmptyState` "Import your client book" with Bulk import + onboarding pipeline CTAs. Guidance here is strong.
7. Rough edges: ~~the consent step's visible copy literally includes the internal note "(manual anchor: #consent)" (`portfolio.tsx` ~line 402) — leaked annotation.~~ _(fixed R64: the annotation is gone.)_ Jargon "stamping", "Layer 1 sharing consent" is unexplained. Nav's "Client import" link is gated on feature `white_label` (launch-dark) but the portfolio header/empty-state "Import clients" buttons check only the `clients.import` capability — at launch they can point into a dark surface.

1. Same accept-invite → /login → client_user auto-routes to /app/. `sme-compliance/src/components/require-session.tsx`: 401 → bounce to /login; wrong role → "Wrong workspace" splash with portal button.
2. `layout.tsx` nav filters by capability AND `Me.features`, so at launch (R62) the sidebar shows: Work = Dashboard, Month-end, Invoices, Import; Compliance = VAT only (VAT link has NO feature gate — it stays visible even though its data surfaces sit behind dark features); Workspace = Calendar, Analytics, Notifications, Alert settings, Consent. Clerk group hidden.
3. `dashboard.tsx` first paint: `WorkspaceHeader` "Compliance overview" with a "New invoice" button (visible next action), a MetricStrip of four zeros, and Today/Money/Compliance tabs.
4. Empty states: WorkQueue → "Today is clear / no urgent submissions…" — for a brand-new book this celebrates instead of orienting; Recent activity → "No recent activity"; Next deadline → "No upcoming deadlines". The ONLY first-run guidance is inside `ReceivablesCard`: "No outstanding receivables. **Create your first invoice** to start tracking what you're owed" (gated by `showFirstInvoiceCta(totalInvoices === 0)`).
5. There is no SME-side getting-started checklist (unlike the console's) — nothing tells a new client_user about granting consent, adding customers, or Import as an alternative path. Import is only discoverable in the nav or via the invoices-list empty state.
